SKALES · PUBLIC DOCUMENTATION

Make work recognizable and recoverable

Skales documentation describes saved sessions, project context, customization and task traces. Its current public repository does not provide the app source; it was inspected, not installed or run. Adapt the interaction lessons; don’t assume access to its internals.

Recommendation: Alegor is the proposed persistent project companion; today it is a deterministic Git/docs snapshot tool. Build a Represent Workspace web shell around project history and linked tools. Add a local agent only for local files or commands. A full desktop is for workflows that truly need GUI apps.

Choose the lightest runtime that fits

These are product scenarios, not claims about a working Represent runtime. Select a workload to see the smallest practical starting point.

Web workspace · start here

For viewing saved project data and opening Grafe/Alegor/Visu, a normal web app is leanest. No Linux environment is needed. Keep analysis on the user’s machine when project files are private or local.

1 · Web workspaceSaved views, timeline, citations and navigation. No container required.
2 · Local serviceToday’s Node services; future narrow connector for an approved checkout.
3 · Isolated Linux jobOn demand when a real task needs builds, tests or a Linux tool.
4 · Full desktopOnly when a proven workflow needs graphical apps.
Separate security boundary: an execution container does not isolate an HTML/JS preview served on the app’s own origin. Render trusted structured artifacts in Represent components; put arbitrary previews on a separate origin in a sandboxed iframe with a narrow typed bridge. If hosting runners later, compare Cloudflare and E2B on the same controlled task before choosing.

Suggested path

Build Represent Workspace as a product experience first. “Represent OS” can stay the metaphor. Ship a web shell that brings project identity, evidence and the three lenses together. Keep today’s local Node services; add an on-demand runner only when real tasks require execution. Compare managed sandbox options on the same job before hosting. A full remote desktop adds operational and security work; choose it when a proven workflow needs GUI interaction.
Research evidence and boundaries
  • Gource: v0.53 run captured 427 frames at 25 fps for GoCity (first pass), with a retained middle frame. It visualizes file activity and contributors over history, not semantic call relationships. Official Gource site · source.
  • Grafe: tested on Plane Sync and Represent; deterministic JS/TS indexing, source snippets and relations. It is not an all-language graph and does not claim runtime behavior.
  • Codevis: the Notion screenshot identifies divan/codevis; GitHub currently returns 404 and the cause is unknown. The public KDE/codevis is distinct.
  • Skales: inspected current repository README and public guide. Source is unavailable and app was not run. Skales repository.
  • Dot: screenshot and official docs support a companion/workspace interaction, but not its internal OS/container architecture.
  • Alegor: current MVP snapshots local Git and selected project docs; no session connector, autonomous action, or Linux execution environment yet.
  • Research scope: first-person Notion notes are user-specific design evidence, not market validation. The workspace concept remains a hypothesis for testing.
