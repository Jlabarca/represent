# Notcards development implementation

The source review checked Google identity and account ownership in src/notcards, the Chrome identity handoff and capture queue in extensions/notcards, and the scope of the development deployment described in docs/guides/notcards-dev.md. Independent review identified concurrent storage reservations and missing limits in the guide. The hosted store now holds a per-account lock across capacity checks and writes. A competing final-slot test covers the failure. The operator guide documents notebook, folder, storage and image limits.

Browser evidence in experiments/notcards/dev shows the real public thumbnails in both desktop themes and at 390 pixels. An isolated signed-in Chromium fixture opened a private text notebook, reopened the warm collection and showed only public samples after logout. The lab1 origin served the development ZIP byte-for-byte, rendered the Notcards shell without developer pairing and returned HTTP 401 for signed-out private notes. The registered proxied CNAME and Google web client are now live. Public HTTPS browser checks pass and the real sign-in opens the Google account chooser. Private Google consent awaits the owner choosing their account. The full test-file inventory ran under Linux except the Windows NTFS junction suite, which ran natively. Gateway Apply, paid inference and Chrome Web Store publication have separate acceptance steps.
