# Visualization reference repositories

## What should Represent reuse from interactive-diagram?

### Takeaway
Use its config-only authored views, offline SVG delivery, details panel, and explicit geometry audit as the small-renderer reference. It is a curated diagram generator, not evidence of scalable repository understanding or hierarchical level-of-detail.

### Cited Findings
- Official origin verified through GitHub and local git remote: https://github.com/LizardLiang/interactive-diagram.git; shallow clone at `D:/ware/represent/references/interactive-diagram`, pinned SHA `1e252e62fd07631e71316179bc00861f52c6292b`. License filename `LICENSE`, identifier MIT. — [license](https://github.com/LizardLiang/interactive-diagram/blob/1e252e62fd07631e71316179bc00861f52c6292b/LICENSE#L1-L21)
- The authored contract is an embedded `app` object. Tabs carry diagram type and containers/blocks/edges; block identities and container membership are explicit. The runtime is separate from authored configuration, but the artifact is executable HTML rather than a neutral JSON scene. — [config](https://github.com/LizardLiang/interactive-diagram/blob/1e252e62fd07631e71316179bc00861f52c6292b/assets/skeleton.html#L534-L730)
- Label measurement precedes geometry: wrapping and block fitting are explicit functions, followed by a layout guard covering blocks, labels, titles, and containers. The guard orders/settles nodes and zones rather than relying on an unseeded force simulation. — [label fitting](https://github.com/LizardLiang/interactive-diagram/blob/1e252e62fd07631e71316179bc00861f52c6292b/assets/skeleton.html#L732-L810); [layout](https://github.com/LizardLiang/interactive-diagram/blob/1e252e62fd07631e71316179bc00861f52c6292b/assets/skeleton.html#L995-L1328)
- The geometry audit reports residual conflicts; corrective iteration is bounded to four outer passes. That bounds resolver iterations, not total node count, memory, or dense-graph runtime. — [audit](https://github.com/LizardLiang/interactive-diagram/blob/1e252e62fd07631e71316179bc00861f52c6292b/assets/skeleton.html#L1468-L1560); [passes](https://github.com/LizardLiang/interactive-diagram/blob/1e252e62fd07631e71316179bc00861f52c6292b/assets/skeleton.html#L4742-L4800)
- Interaction logic includes upstream/downstream chain highlighting; ER uses immediate neighbors because transitive reachability could light almost everything. This is a useful concrete example of tailoring selection to the view's semantics. — [chain versus neighbors](https://github.com/LizardLiang/interactive-diagram/blob/1e252e62fd07631e71316179bc00861f52c6292b/assets/skeleton.html#L3823-L3860)
- Details show description, code, technology tags, and responsibilities. Code/description use textContent, but technology and responsibility arrays enter innerHTML, so scanner/LLM-derived strings must not be passed through this renderer unchanged without escaping. — [details](https://github.com/LizardLiang/interactive-diagram/blob/1e252e62fd07631e71316179bc00861f52c6292b/assets/skeleton.html#L4130-L4146)
- Theme selection persists locally; export builds SVG snapshots and PNG output. This is appearance/theme switching, not a demonstrated external ontology-to-primitives theme-pack interface. — [theme](https://github.com/LizardLiang/interactive-diagram/blob/1e252e62fd07631e71316179bc00861f52c6292b/assets/skeleton.html#L4162-L4183); [export](https://github.com/LizardLiang/interactive-diagram/blob/1e252e62fd07631e71316179bc00861f52c6292b/assets/skeleton.html#L4212-L4350)
- Import/upgrade tooling preserves the embedded config and title while replacing the runtime. Its config extraction explicitly uses a marker and brace-count heuristic, not a full JS parser. Avoid this as Represent's durable ingestion boundary. — [splice implementation](https://github.com/LizardLiang/interactive-diagram/blob/1e252e62fd07631e71316179bc00861f52c6292b/scripts/splice.mjs#L1-L53)
- Actual local execution on 2026-10-21: `node D:/ware/represent/references/interactive-diagram/scripts/regen-examples.mjs` exited 0 and regenerated all eight bundled examples. `git status --short` afterward returned empty: regeneration matched committed fixtures byte-for-byte. This exercised the supplied template/config splice workflow, not browser geometry. — [executed script](https://github.com/LizardLiang/interactive-diagram/blob/1e252e62fd07631e71316179bc00861f52c6292b/scripts/regen-examples.mjs#L11-L58)

### Inferences
- Adapt the view config separation: derive bounded, purpose-specific diagrams from a richer persistent scene. Keep source evidence (path, symbol, line span, revision) in Represent's neutral contract and expose it in the details panel; the inspected config is authored narrative, not trustworthy source provenance by itself.
- Adapt the audit as a renderer acceptance gate: legible labels, no unintended overlaps, and visible unresolved conflicts. Determinism on identical input does not imply small edits preserve placement; test this separately.
- Reuse the HTML examples as interactive prototypes with MIT notice retention, but do not wholesale adopt a nearly 5,000-line monolithic HTML runtime as the headless core.

## What should Represent reuse from CodeCharta?

### Takeaway
Its strongest reusable ideas are the explicit identity layer plus additive analysis lenses, independent view state, and contextual filtering that retains ancestry. Treat its 3D metrics city as an alternative view and its source code as design evidence; it was not built or interactively tested in this session.

### Cited Findings
- Official origin verified through GitHub and local git remote: https://github.com/MaibornWolff/codecharta.git; shallow clone at `D:/ware/represent/references/codecharta`, pinned SHA `4e8dfb60d2aae6472a7c725bf9f044133f965d28`. License filename `LICENSE.md`, identifier BSD-3-Clause (also declared in package metadata). — [license](https://github.com/MaibornWolff/codecharta/blob/4e8dfb60d2aae6472a7c725bf9f044133f965d28/LICENSE.md#L1-L25); [package](https://github.com/MaibornWolff/codecharta/blob/4e8dfb60d2aae6472a7c725bf9f044133f965d28/package.json#L1-L16)
- cc.json 2.0 separates meta, a nested file identity tree, and additive lenses. File identity is derived from canonical path; contentHash and link are optional. This cleanly separates identity from metrics and analysis overlays. Path-derived identity still changes on rename. — [wire schema](https://github.com/MaibornWolff/codecharta/blob/4e8dfb60d2aae6472a7c725bf9f044133f965d28/dev_docs/cc-json-2.0.schema.json#L1-L66)
- Dependency lenses distinguish physical file edges from declarations and namespace membership, including declaration edges that would disappear after collapsing to file-level edges. Unknown top-level lenses are documented as round-trippable. — [lenses](https://github.com/MaibornWolff/codecharta/blob/4e8dfb60d2aae6472a7c725bf9f044133f965d28/dev_docs/cc-json-2.0.schema.json#L60-L140)
- Runtime nodes carry nested children, metric attributes, optional link/path, exclusion state, deltas, and optional fixed rectangles. Layout choice includes squarified treemap, street, sunburst, and radial treemap. — [domain model](https://github.com/MaibornWolff/codecharta/blob/4e8dfb60d2aae6472a7c725bf9f044133f965d28/visualization/app/codeCharta/model/domain.model.ts#L9-L75)
- Treemap generation uses d3-hierarchy; fixed-folder positions can be preserved while children are laid out within them. Label padding is capped as a fraction of a folder; the declared labelled hierarchy boundary is three. These mechanisms help hierarchy/readability but do not prove dynamic LOD or general layout stability. — [treemap implementation](https://github.com/MaibornWolff/codecharta/blob/4e8dfb60d2aae6472a7c725bf9f044133f965d28/visualization/app/codeCharta/renderer/threeViewer/algorithm/treeMapLayout/treeMapGenerator.ts#L1-L106)
- Searching a radial map preserves paths leading to hits and their ancestors; other nodes are flattened/greyed. This retains spatial context rather than removing every nonmatching item. — [search-aware flattening](https://github.com/MaibornWolff/codecharta/blob/4e8dfb60d2aae6472a7c725bf9f044133f965d28/visualization/app/codeCharta/renderer/renderModel/flatness/mapFlattenPredicate.selector.ts#L1-L31)
- Appearance is part of view state (mapColors, color labels, mode/range), separate from the domain tree; JSON download uses a browser Blob. — [view state](https://github.com/MaibornWolff/codecharta/blob/4e8dfb60d2aae6472a7c725bf9f044133f965d28/visualization/app/codeCharta/model/state.model.ts#L100-L130); [download](https://github.com/MaibornWolff/codecharta/blob/4e8dfb60d2aae6472a7c725bf9f044133f965d28/visualization/app/codeCharta/util/fileDownloader.ts#L1-L11)
- It provides a full Angular/Electron visualization build/test surface, unlike the single-file diagram. Node version constraints, development/build scripts, Jest tests, and Playwright tests are explicit. Bundled sample cc.json assets provide future demo inputs. — [build surface](https://github.com/MaibornWolff/codecharta/blob/4e8dfb60d2aae6472a7c725bf9f044133f965d28/visualization/package.json#L13-L56); [sample fixture](https://github.com/MaibornWolff/codecharta/blob/4e8dfb60d2aae6472a7c725bf9f044133f965d28/visualization/app/codeCharta/assets/sample1.cc.json)

### Inferences
- Adapt identity + overlays within the existing Represent scene contract rather than replacing scene.yaml with cc.json. Keep observed facts separate from derived clusters, explanations, and view selection.
- Adapt fixed cluster anchors and ancestor-preserving search. Explicitly test movement after local source edits, renames, changed metrics, and filtering; fixed coordinates alone are insufficient evidence of stable layout.
- Reuse metric-city views when comparing size/hotspots; do not make a metrics city the only architecture narrative. Keep source provenance available independently of visual encoding.
- Avoid importing its entire Angular/Electron/Three.js application into a minimalist companion before a smaller SVG prototype proves insufficient.

### Gaps
- CodeCharta was source-inspected only. Dependencies were not installed, no build/test suite ran, no import/export round trip occurred, and no screenshot or interaction is claimed.
- Optional path/link fields establish a place for traceability, not proof that line-level navigation is implemented or reliable. No hard renderer memory/node budget or measured large-project latency was established.
- The repository contains both older visualization API metadata and new cc.json 2.0 schema. Compatibility must be tested via actual import fixtures before claiming the new schema is universally supported.
