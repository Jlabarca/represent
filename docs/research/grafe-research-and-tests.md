# Grafe research, repository genealogy, and test record

> Research snapshot: 2026-10-21. This is a source and experiment ledger for the Grafe technical explorer. It distinguishes original user notes, inspected references, executable trials, and current MVP decisions. It does not claim market validation.

## System Intent

Grafe is the technical way to explore a codebase inside the Represent suite. Its job is to help a developer answer a concrete question—what is this thing, where is it defined, what does it use, what uses it, and what might a change touch—then open exact source evidence. A readable focused neighborhood with snippets is the product target; a full-repository graph is not a useful default. The name is a working track name, not a locked brand decision.

This direction came from the user’s Notion export, which I read directly at `D:/ware/represent/notion/Pixel Clay - Represent Code Graphics Representatio d2122e06d68d451c9f980fa24256b9f4.md` and its linked `11 abril Attempt`, `MiniMap`, `Code runtime doctor`, `Research`, `What if`, and `Go Visual` notes. I also opened the attached `Untitled.png` image; a preserved copy is [the original Codevis screenshot](../../experiments/grafe-reference-checks/notion-codevis.png). The image itself visibly names `github.com/divan/codevis/cmd/codevis` and shows code excerpts inside graph nodes. The raw image was copied byte-for-byte for this report (SHA-256 `E105F7D0C9C9997D30F67EFDD19356D48951183C64E1FCE85E655282208E8306`); the original Notion export was not edited.

The April note asks for visible code structures—lists, dictionaries, pools, state machines—plus counts, interactions, and adjustable technical depth. It also asks for an image or viewer that can be embedded in an IDE or web surface. The MiniMap note describes a map that follows the current code location and zoom, zooms back to the whole project, and can be detached from following. The main note separately imagines runtime/build profiling, uncertainty and runtime paths, themed visual encodings, and efficient operation on large repositories. These are design leads from the owner, not independently validated user needs. Runtime profiling and broad theme authoring are larger tracks; neither is silently included in the current code-navigation MVP.

The exact `divan/codevis` GitHub URL is unavailable today: opening `https://github.com/divan/codevis` returns GitHub 404. Divan’s own post calls Codevis an unnamed, early-alpha experiment, which supports the identity shown in the screenshot but does not establish whether that repository was later made private, deleted, or moved. The public [`KDE/codevis`](https://github.com/KDE/codevis) is a distinct C++ maintenance visualizer. Its official guide describes a generated code database, package/namespace navigation, forward and reverse dependencies, edge-depth controls, details for covered nodes, and a whole-graph minimap that marks the viewport. Its source docs are valuable UX research, but it is not the Go screenshot project and its C++/Clang project database is not Grafe’s current TypeScript indexing implementation.

## Ingestion Vector

The current Grafe test set separates synthetic fixtures (known expected relations) from a small real Node repository (real path resolution and actual source ranges). The tree below describes the tested real target, not every file that an MVP scanner should index. The plane-sync checkout was inspected read-only at revision `a1a91c4fa80888c2be0a7898dfb91bf7e42c5cd3`; it had 21 tracked files and a one-file `src` directory. The decoded SCIP index actually named six documents, including tests and a tool, so the observed index scope differed from the first command’s narrow-looking `src` dependency-cruiser scope.

```text
plane-sync/                         # @LLM-ENTRY: real small Node service used for adapter trials
├── README.md                       # @LLM-TARGET: declared role and setup
├── package.json                    # @LLM-TARGET: scripts, runtime and project metadata
├── src/index.js                    # @LLM-TARGET: HTTP entry point and implementation symbols
├── runner/                         # @LLM-TARGET: related workflow code found in decoded SCIP index
├── test/                           # @LLM-TARGET: candidate test relationships; must be evidenced
├── tools/                          # @LLM-TARGET: support code found in decoded SCIP index
├── node_modules/                   # @LLM-IGNORE: third-party code
└── generated or build output/      # @LLM-IGNORE: output should not become architecture by accident
```

The synthetic `experiments/grafe-research/fixture/` and `experiments/grafe-restart/fixture/` projects provide controlled cross-file imports, type references, calls, definitions, and plain reads. A source span is only accepted when its range can be checked against the exact fixture text. SCIP is one extractor format in the experiments, not a claim about the builder’s current implementation. The current build decision is to start with the TypeScript compiler API directly: the prior SCIP work proves that an alternative index can carry useful ranges, while also exposing extra binary-decoding/cache/tooling complexity. Do not describe SCIP as rejected for poor indexing quality; the tests found accurate spans.

Recommended growth of ingestion scope is gradual: visible file preview and ignores first; then project/package boundaries; then language-aware symbols and references; then explicitly evidenced test links and change-impact paths. Every relation should carry a kind and provenance. A failed or unsupported parser must be surfaced as a coverage diagnostic; a zero-edge result must never imply there are no relationships.

## Visualization Spec

The owner’s screenshot gives Grafe an unusually direct quality reference: code and identifiers belong in selectable nodes, but the original image also demonstrates why density must be controlled—the `main` node’s fan-out becomes a web of crossing lines and snippets overlap at overview scale. The current design response is a selected symbol/file and a small neighborhood, paired with an outline/list and a detail pane containing exact excerpts and source locations. The user should be able to search, focus one node, switch direction or relation kind, follow one edge, and return to a broader package/repository context. Details should remain reachable without hover-only controls.

The trajectory across references suggests three different jobs, not one visualization to copy wholesale:

1. **Project evolution:** animate Git changes through time (Gource/Git City). This is about when and who changed paths.
2. **Structural overview:** aggregate project/package/files and metrics (GoCity/CodeCharta). This is about shape and hotspots.
3. **Semantic navigation:** select a symbol and inspect typed relations and source evidence (Codevis/SCIP/GitNexus/CodeBoarding). This is Grafe’s MVP center.

The possible future “code minimap” should be an overview and viewport cue linked to the selected source/editor position, not a second graph that competes with the local interaction. A runtime view must say whether its edges came from a static parser, profiler, trace, declaration, model, or user annotation. Aesthetic themes can change how entities are drawn, but they must not change the meaning of relation types or hide uncertain evidence.

### Trial ledger and reproducible evidence

**A. Dependency and symbol-index smoke on a two-file fixture.** The local fixture contains an `index` importing a `user` module. `npm exec --yes --package dependency-cruiser@18.7.0 -- depcruise --no-config --output-type json --output-to ... D:/ware/represent/experiments/grafe-research/fixture/src` exited 0 and returned 2 modules/1 internal import. The SCIP command used `npm exec --yes --package @sourcegraph/scip-typescript@0.4.0 -- scip-typescript index --cwd ... --output ../scip-typescript-trial.scip --no-progress-bar`; it completed in 22ms. This verified tool launch and a basic relation, not accuracy of all kinds or a complete application.

**B. Read-only plane-sync comparison.** At revision `a1a91c4fa80888c2be0a7898dfb91bf7e42c5cd3`, plane-sync had 21 tracked files and one source file in `src`. dependency-cruiser resolved four Node built-in imports and no internal `src`-to-`src` dependency; that is expected for the command’s chosen scope. SCIP with `--infer-tsconfig` completed in 599ms and wrote a 353,427-byte binary, but inference also created a `tsconfig.json` in the target. That exact generated file was moved to the experiment folder and the source worktree was verified clean. The first report correctly marked the binary undecoded and its input file set uncertain.

**C. Decoder and focused viewer.** The restart spike indexed a synthetic four-file TS project with the pinned SCIP package and decoded it using the generated protobuf classes. It found four documents and 39 occurrences; all non-container occurrence spans matched exact source text. Decoding the saved plane-sync index found six document paths (`runner/afkbot.mjs`, `src/index.js`, three tests and `tools/board-structure.js`), 1,075 symbol records, 6,485 occurrences and zero measured span mismatches. Counts are limited to those six observed documents; they do not prove repository completeness or call resolution. ### Ghost AI Plan

The measured technical-navigation path does not require an AI request: file identity, parser/indexer relations and source excerpts should be deterministic. If Ghost is later used to name a cluster or explain a selected path, send only bounded evidence-backed inputs through Represent’s Ghost gateway; return source evidence IDs and explicit uncertainty; cache by snapshot, prompt/model, and selected scope; and never run a model automatically on hover. There were zero paid model calls in the fixture/index/viewer trials. The prior Graphify experience is a reason to expose truncation/completeness diagnostics and avoid spending on every refresh, not a reason to remove the gateway decision.

### Embeddability Plan

Keep index records and queries in a headless snapshot library/CLI; keep the graph/outline/details pane as a thin web view. An editor integration should pass a repository revision and current file/symbol selection into the same query contract; a detached minimap can later consume the same selected-node and viewport state. Desktop, mobile, IDE plugins, CLI and library use are future shells rather than separate parsers. Export must preserve evidence links and scope. This is a proposed seam; the current MVP build’s actual supported surfaces should be recorded in its completion report.

### What remains unproven

- The historical tiny Node target and synthetic fixtures do not establish parser coverage on a large TypeScript monorepo, incremental refresh cost, memory use, or language portability.
- Zero source-span mismatches only applies to the specific documents and occurrences checked. It does not establish call-target correctness, tests affected, or absence of missing edges.
- No controlled developer usability study has measured onboarding or change-impact task success. Repository stars and marketing claims in references are not a substitute.
- The divan Codevis GitHub repository cannot currently be inspected at the exact URL; the reason is unknown. The separate KDE Codevis has its own source and scope.
- Automated task checks and screenshot review passed for the completed local MVP below. An unaided maintainer study and larger multi-package repository trial remain unperformed.

## Completed MVP: real projects, review findings and decisions

The [implementation reference](../reference/grafe-mvp.md) describes the library, CLI and local web product; the [MVP experiment record](../../experiments/grafe-mvp/README.md) links reproducible scripts, JSON measurements and screenshots. This is a separate implementation from the earlier static SCIP viewer. The integrated repository regression suite passed **57/57**, including **10 Grafe core/API tests**; its final browser script passed **16/16** with zero page errors.

The first Represent trial covered 34 files and is retained as `initial-real-project-audit.json`. After both MVPs were integrated, the final scope contained **51 files / 347,468 bytes / 244 symbols / 2,036 relationships / 1,449 diagnostic groups**, indexed in **952.82ms**. Plane Sync covered **6 files / 101,151 bytes / 75 symbols / 437 relationships / 205 diagnostic groups**, indexed in **783.95ms**. The report records exact selected files/hashes and HEAD `34a79ca3cba61ed9fc19972cb6ec335304e1e709`; then-uncommitted files mean the commit alone is not the full sample identity. Diagnostics are visible coverage limits, not proof that a missing relation does not exist.

The audited Plane Sync question was “who calls `upsertImpl`, and what related tests exist?” The graph found `fullSync` at `src/index.js:423`, `handlePostLink` at `:712`, and `handleForcedSync` at `:729`. Five dynamic-import test mentions remain explicitly **candidates**. Represent's `analyzeProject` showed seven checker-linked test references; passing it as a constructor value is not misrepresented as a direct production call. Changing `runner/afkbot.mjs` only in a disposable copy changed the snapshot while unaffected symbol IDs stayed stable; unchanged indexing reused the original snapshot. The source project's HEAD, status and selected source hashes stayed unchanged.

The design round chose search/outline → selected neighborhood → exact evidence, with an alternative relationship list. Live review then fixed false same-name links, class-field arrow ownership, a nonfunctional Evidence toggle, outgoing-row navigation and stale graphs on project switching. The UI round fixed stretched layout, overlapping graph cards and an oversized single search row. Desktop panes scroll independently; the graph shows at most five incoming and five outgoing neighbors with remaining counts. Dark mode, keyboard controls and a 390px mobile layout were exercised. Screenshots and geometry/contrast assertions are linked in the experiment record. Automated interaction checks do not establish unaided usability.

This MVP makes **zero AI/API calls**. Its TypeScript checker sees captured source plus its own standard library; it does not execute the project or traverse arbitrary project references. Current limits are JS/TS, bounded scope (2,000 files, 1MiB/file, 32MiB total), unresolved runtime/dynamic/external relationships, and full bounded rebuilds. Next independent Grafe work should test a larger multi-package repository, then editor-follow/minimap interaction and measured incremental indexing. Gource-style replay remains a possible history view with a different data contract. Open-source adapters, exact evidence records and regression fixtures are plausible community contributions; the [developer-needs study](research_notes/Represent%20parallel%20track%20restart/developer-needs.md) supplies opportunity hypotheses, not adoption or willingness-to-pay validation.
