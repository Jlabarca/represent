# Notcards and the existing Causa Botanic deployment

## Notcards development

The live website uses the newer dedicated Google web client. Its callback is `https://not.maremoto.dev/auth/google/callback`. The live flow reaches the standard Google account chooser. Signed-in and signed-out isolation has also been exercised independently with fixture accounts.

Use one shared Notcards assistant, one conversation per card after the first submitted question, and an optional project per collection. Notcards owns each note and its revisions. The native Botanic overlay validates a registered site, private assistant and current LibreChat user. Its existing workflow binding is for reconciliations. Notcards needs its own owner-scoped card binding, verified issuance or provider mapping, notes-only context API and separate inference attribution. The binding needs owner/card and owner/conversation uniqueness. Botanic must establish ownership of its conversation and check the Notcards site assistant before resuming. Google social login and the exact-issuer OpenID hook use different Botanic provider paths. Provision through a verified issuer/subject exchange or an explicit, reviewed provider mapping. The implementation sequence and acceptance criteria are in the [Notcards roadmap](../design/clay-notes-service-roadmap.md).
